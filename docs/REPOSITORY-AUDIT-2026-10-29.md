# MarketingOS source review — 2026-10-29

**Status: partial audit; not a production-readiness certification.** This is a source-evidenced snapshot of the areas changed on this branch, not a complete review of every route, view, integration, dependency or deployment configuration. The tree contains 175 API route files and 45 view files; large areas remain unaudited. Historical statements of completeness or readiness should not override the evidence below. No production database, provider or host was accessed.

Classification used below: **partial** = some real, locally tested functionality, with material gaps; **disabled** = intentionally fails closed; **unverified** = code exists but end-to-end behavior is not established. The A–H grouping is an inventory aid, not a claim that the original full audit is complete.

| Area | Observed status and source evidence | Required work / security boundary |
| --- | --- | --- |
| A. Authentication, tenants, SetupBot | **Partial.** Database-backed sessions, scoped roles (`src/lib/auth.ts`, `src/lib/agency.ts`); encrypted, resumable bilingual onboarding and lockout (`src/lib/setup-bot/`, `src/lib/login-lock.ts`; `tests/setup-bot-*.test.ts`). Global account and backup operations are restricted to interactive system administrators. | SetupBot's proposed additive schema is **not deployed**; verify secure proxy, key custody, retention and live provider checks. Existing bearer tokens in browser local storage increase XSS risk. Per-process rate limiting is not a distributed control. Audit all remaining tenant/role boundaries. |
| B. AI workforce and knowledge | **Partial.** Agent specs and scoped retrieval exist (`src/lib/workforce/engine.ts`, `src/app/api/workforce/`, `src/lib/agent-tools.ts`). Seeded agent records are not evidence of agents executing. Sensitive SOPs/knowledge are suppressed where role-aware scope is not implemented. | Finish review/approval, secure access policies, budgets, scheduling, job state, operational monitoring and isolation for every tool. No live model was verified. |
| C. Campaigns, social and content | **Partial / disabled external publishing.** Content is planning-only and manual publication claims are rejected (`src/app/api/content/`, `src/app/api/social-accounts/`). Scheduled dates do not run a publisher. | Implement official authenticated publishing, media validation, human approval, idempotency, rate limits, remote IDs and status reconciliation. Review legacy records and other routes before exposing them. |
| D. CRM, email, SMS, voice and consent | **Partial / disabled live sending.** Email creates drafts only; SMS, broadcasts, OTP and VoIP fail closed (`src/lib/outbound-safety.ts`, `src/app/api/email/send/`, `src/app/api/sms/`, `src/app/api/voip/`). | Implement verified consent, suppression/opt-out, legal policy, provider-specific 2FA and actual delivery state before enabling sends. Existing legacy OTP-like rows are retained and withheld, not automatically deleted. Audit all CRM and outreach routes. |
| E. Image, video, audio and personas | **Partial / unverified providers.** Local adapter code exists; browser animation and estimated captions are labelled; `src/app/api/brand/personas/[id]/render/` and `src/app/api/media/lipsync/` return unavailable rather than claim work or send arbitrary likenesses. | No durable render queue or worker, trusted consent-to-asset binding, output verification or live hardware test. Persona records contain user-asserted references, not proof of consent; role-aware editing and ownership verification need broader review. Paid media controls need durable approvals, budgets and retry idempotency. |
| F. Analytics and dashboard | **Partial.** `src/app/api/analytics/route.ts` and `src/app/api/dashboard/route.ts` expose tenant-scoped CRM counts and unavailable provider KPIs rather than invented results. | Provider-backed collection, attribution, timestamps, remote IDs, validation and reconciliation are missing. Historical campaign JSON is not proof of delivery or performance. |
| G. Workflow and automation | **Partial.** Manual, bounded local `log_activity`, `create_notification` and draft-only `email` steps are transactional with idempotency/history (`src/lib/workflows.ts`, `src/app/api/workflows/execute/route.ts`; `tests/marketing-safety-routes.test.ts`). | No scheduler, external actions, durable retries or crash recovery; a crash may leave a run `running`. Add leased jobs, reconciliation, approvals, pause-all, audit and replay tests before calling it an autonomous engine. |
| H. Infrastructure, data, CI and other modules | **Partial / broadly unverified.** Backup endpoints require system admin; schema sync has a backup/diff guard (`src/lib/backup.ts`, `scripts/db-sync-schema.sh`). CI runs tests, lint, build, secret scan and dependency audit (`.github/workflows/ci.yml`). | No complete Prisma migration baseline, production backup/restore rehearsal, deploy, browser test or infrastructure audit. SEO, ads, secure asset handling and numerous legacy routes/views need independent review. Pattern-based secret scans are not proof that no secret exists. |

## Test and migration evidence

See [TESTING-AND-DEPLOYMENT.md](TESTING-AND-DEPLOYMENT.md) for exact local commands and boundaries. The proposed SQL in `prisma/changes/20261029_setupbot_additive.sql` covers five SetupBot/auth tables only; it is not a registered Prisma migration and is not a complete baseline. Client provisioning is not fully transactional. Do not apply any schema change to real data without owner approval, a verified backup and a tested restore.
