# Integrations and credentials — current boundaries

This branch was tested with disposable data and mocked providers. **No live provider credential, real publication, outbound message, paid generation or provider delivery has been verified.** Configure secrets only in a server-side secret manager or other owner-approved secure channel, never in source, chat, logs, URLs or browser bundles. See `.env.example` and [SETUP-BOT.md](SETUP-BOT.md) for the current variable names and detailed onboarding/retention limits.

| Integration | What exists | Still needed / verification |
| --- | --- | --- |
| SetupBot local import | Encrypted draft/import, local confirmation, read-only Meta Page/WhatsApp identity checks and webhook challenge logic. | `JWT_SECRET`, a separate 32-byte `CREDENTIAL_ENCRYPTION_KEY` in 64-hex form, trusted HTTPS proxy and a reviewed database schema. Tests mock remote responses. Meta version and scopes must be checked in a real authorized environment; token acceptance is not publishing permission. |
| SetupBot optional remote handoff | HTTPS receiver with mapped project IDs, service bearer, acknowledgement and idempotency. | Separately generated `ADMIN_SERVICE_TOKEN`, `SETUP_HANDOFF_BASE_URL`, `SETUP_HANDOFF_PROJECT_MAP`; sender and receiver currently require the same encryption key. Configure secure sharing and log/query redaction. External receivers need compatible idempotency. |
| Social publishing | Social account credential verification/storage code exists. | Publishing/sync adapters, official permissions, approval and returned provider IDs are not implemented. Meta's documented flow requires the appropriate account, permissions, media container and publish result: https://developers.facebook.com/docs/instagram-platform/content-publishing/ |
| SMS, email, voice, OTP, WhatsApp | Email drafts only; SMS/voice/OTP endpoints fail closed. WhatsApp ID checks are not a messaging adapter. | Consent evidence, suppression/opt-out, audited sender configuration, provider integration, webhook validation and delivery-state reconciliation. Twilio distinguishes message states: https://www.twilio.com/docs/messaging/api/message-resource and documents consent handling: https://www.twilio.com/docs/messaging/features/consent-api |
| AI text | `src/lib/ai-provider.ts` defaults to self-hosted Ollama and blocks tested paid fallback paths; explicitly free OpenRouter model IDs are supported in the tested router. | Operator-owned model/runtime, network policy and measured resource limits. Self-hosting is not free of infrastructure cost. OpenRouter free availability/quotas change; paid fallback is billable: https://openrouter.ai/docs/guides/routing/routers/free-router and https://openrouter.ai/docs/guides/routing/model-fallbacks |
| Image/video/TTS/music | Optional local adapter code and gated hosted media routes exist. Persona rendering and lip-sync are disabled pending consent binding and a durable worker. | Private configured hardware/adapters and model licenses, output verification, job recovery and consent. Hosted media may incur charges; interactive manager approval exists for relevant requests but durable budgets/approvals and complete cost controls do not. No provider was called in validation. |
| Advertising, verified analytics | No verified end-to-end advertising or analytics integration in this branch. | Owner-provided authorized accounts, app registrations, appropriate scopes, explicit budget/approval controls, verified remote state and reconciled metrics. Do not invent credentials or report estimates as fact. |

A credential saved or a token check passed is not proof of provider delivery, publishing, consent, budget compliance or ongoing access. Provider terms and permissions must be rechecked at implementation and release time. Encryption keys must be backed up separately from database ciphertext; rotation and backup erasure require an explicit plan.
